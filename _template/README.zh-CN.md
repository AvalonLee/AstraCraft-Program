# 条目中文名称

> 一句话定位。上游：[OWNER/REPO](https://github.com/OWNER/REPO) · 许可证：MIT · 🟢 A

## 是什么

它是什么类型的东西（skill / MCP server / CLI 工具 / 框架 / 规范），由谁维护，
处在什么生态位。两三句话讲清楚，不要展开。

## 解决什么问题

**这一段最重要。** 具体描述它针对的痛点场景：在没有它之前你怎么做、麻烦在哪、
它介入之后流程变成什么样。

避免写成"提供了强大的 XX 能力"这种没有信息量的句子。

## 怎么装

```bash
# vendored 条目：直接从本仓库拷走
cp -r src/ ~/.claude/skills/<skill-name>/

# Windows Git Bash
cp -r src/ "$USERPROFILE/.claude/skills/<skill-name>/"
```

如果有依赖（Python 包、Node 模块、系统工具、API Key），在这里列清楚，
包括最低版本要求。

## 怎么用

给出**最小可运行示例**。一段能直接复制执行的命令或对话，以及预期输出是什么样。

如果它是 skill，写清楚触发条件——什么样的提问会让 Agent 加载它。

## 亮点

- 具体的、可验证的优点。带上依据
- 比如"内置 14 个 subskill，覆盖从需求澄清到验收的完整链路"
- 而不是"设计精良、功能强大"

## 局限

**别跳过这一段。** 一份只有优点的介绍没有参考价值。

- 什么场景下不适合用它
- 有什么已知 bug 或设计缺陷
- 依赖是否过重、上手成本是否高
- 和同类项目比，它输在哪
